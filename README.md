# 瑜伽体式教练 / Yoga Coach

用摄像头看你的瑜伽练习，实时打分并给出**具体的**纠正建议——不是"做得不错"，而是"前膝移回脚踝正上方，别超过脚尖"。

```
战士二式 · 右侧
Virabhadrasana II

65 分  ████████████░░░░░░░░

调整建议
1. 前膝移回脚踝正上方，别超过脚尖      前膝对准脚踝: 0.60× → ≤0.22×
2. 后腿蹬直，后脚外缘压实地面          后腿伸直: 142° → ≥165°
3. 前膝屈得太深了，小腿回到垂直        前膝屈度: 65° → 80~110°
```

画面不上传，除首次下载模型外全程不联网。

## 快速开始

```bash
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python -m yoga_coach          # 打开默认摄像头，自动识别体式
```

首次运行会下载约 6 MB 的姿态识别模型到 `~/.cache/yoga_coach/models`，之后不再需要联网。

**Linux** 还需要几个系统图形库（macOS 和 Windows 不用）：

```bash
sudo apt install libegl1 libgles2 libgl1 libglib2.0-0
```

**macOS** 需要在「系统设置 → 隐私与安全性 → 摄像头」里给终端授权，否则摄像头打不开且不会报错。

窗口按键：`q` 退出 · `d` 显示/隐藏每项检查的具体数值 · `r` 重新计时。

### 第一步：摆好摄像头

三条通用要求：

1. **全身入镜**——从头顶到脚。身体只拍到一半时程序会直接说"画面不完整，无法评分"，不会硬凑分数。
2. **摄像头大致与髋同高**。平板支撑例外，要放到接近地面的高度。
3. **背景简单、光线均匀**。逆光和杂乱背景会让关键点抖。

### 第二步：一次练习怎么走

```
--list-poses 看机位  →  --pose 锁定单个体式  →  按 d 打开数值
   →  照着建议调整   →  分数上到 78 以上开始计时  →  保持
```

**新手建议先用 `--pose xxx` 锁定单个体式**，不要一上来就用 `auto`。锁定模式下程序不会切换判断对象，你更容易看出某条区间准不准。熟悉之后再用自动模式串练。

想一次看全所有检查项，用照片模式最快：

```bash
python -m yoga_coach --source my_warrior2.jpg
```

它会打印该体式**全部**检查项的实测值、目标区间和未能测量的项，比在镜头前一条条试快得多。

### 第三步：怎么读屏幕上的反馈

| 你看到的 | 含义 |
| --- | --- |
| 左上角大数字 | 当前分数，颜色：绿 ≥85 / 黄 ≥70 / 红 <70 |
| 骨架变绿 | 分数 ≥85 且画面完整，姿势到位了 |
| 关节被标红圈 | 这个关节是某条建议指向的位置 |
| 「调整建议」1/2/3 | 按严重程度排序，先改第 1 条 |
| 「已保持 X 秒」 | 分数持续 ≥78 才计时，掉下去就归零 |
| 「画面不完整，无法评分」 | 身体没入全，先退后或调整机位 |
| 「体式到位，保持住！」 | 所有检查项都通过了 |

**按 `d` 展开数值**，这是调整时最有用的信息：

```
1. 前膝屈得太深了，小腿回到垂直
   前膝屈度: 65° → 80~110°        ← 当前 65 度，目标 80~110 度
```

建议一次最多给 3 条，因为保持体式时能同时想的事情就这么多。改掉一条，下一条会自动补上来。已经改对的建议会立刻消失，新的建议则会等 1.2 秒再换，免得文字每帧乱跳没法读。

表格里 `×` 结尾的目标值是**躯干长度的倍数**（肩中点到髋中点的距离为 1）。这样表达的好处是你走近走远，判断标准不变。

「权重」是这条规则在总分里的分量，也决定它在建议列表里的优先级——权重高的问题会先被提出来。

### 分数怎么解读

- **85 分以上**：骨架变绿，主要对位都到了。
- **78 分以上**：开始计时保持。这个门槛比"完美"低，因为练习中能稳定保持才是重点。
- **70 分以下**：分数条变红，通常有一处明显的对位问题。
- **分数低不等于你做错了**。目标区间是通用课的口令，不是你的个人标准。柔韧度、身体比例、伤病史都会改变什么叫"正确"。

### 常见误判和排查

| 现象 | 多半是因为 |
| --- | --- |
| 一直说"画面不完整" | 脚或头出画；退后一点或把摄像头放远 |
| 分数在两个体式之间跳 | 用了 `auto` 且姿势介于两者之间；改用 `--pose` 锁定 |
| 明明做对了却扣分 | 机位不对。侧身体式用了正面机位，角度会被压缩 |
| 关键点乱飘 | 宽松衣物、逆光、背景杂乱；换 `--model full` 也会稳一些 |
| 左右判反 | 摄像头默认镜像，如果你在看录像回放，加 `--no-mirror` |
| 下犬式/平板分数异常 | 摄像头太高。这两个体式要放到接近地面的高度 |

### 觉得某条区间不合适怎么办

这很正常——区间是按通用课的口令定的。按 `d` 记下**体式 + 检查项名 + 实测值 + 你的体感**，然后改 `yoga_coach/poses.py` 里对应 `Check` 的 `low` / `high`：

```python
Check(
    key="front_knee_bend",
    low=80.0, high=110.0,   # ← 改这两个数字
    ...
)
```

改完跑一遍 `python -m pytest tests -q`，测试里的合成骨架断言会立刻抓出改过头的区间。

## 技术方案

### 识别层

MediaPipe 1.x Tasks API 的 `PoseLandmarker`，每帧输出 33 个人体关键点（归一化坐标 + 可见度）。模型 `.task` 文件首次运行自动下载并缓存，用临时文件原子落盘——下载中断不会留下半个模型被后续加载。lite 模型在普通笔记本 CPU 上约 22ms/帧，够实时。

### 判断层：为什么用规则引擎而不是训练模型

端到端模型的问题是**输出不可解释**：它能说"这个姿势不标准"，说不出"哪里不标准、差多少、怎么改"。而后者才是练习时真正有用的东西。规则引擎还有两个附带好处：加新体式只要写规则，不用收数据重新训练；判断逻辑可读可改，区间不适合你就直接改数字。

代价是规则要手写，且只覆盖能从二维投影看出来的东西。

### 一条规则长什么样

```python
Check(
    key="front_knee_bend",
    label=Text("前膝屈度", "Front knee bend"),
    metric=m.joint_angle("{s}_hip", "{s}_knee", "{s}_ankle"),
    low=80.0, high=110.0, falloff=35.0, weight=1.4,
    when_low =Text("前膝屈得太深了，小腿回到垂直", ...),    # 过头
    when_high=Text("前腿再屈深一点，大腿趋向平行地面", ...),  # 不够
    focus=("{s}_knee",),
)
```

区间内满分，超出后线性扣分，偏离 `falloff` 归零；总分是所有**测到了的**规则的加权平均 ×100。

`{s}` 是"工作侧"（战士系列的前腿、树式的支撑腿），`{o}` 是另一侧。`focus` 让画面上那个关节标红，建议才有指向。

### 几个关键取舍

**所有距离除以躯干长度。** 你走近走远，建议不变。

**过头和不够给不同的话。** "膝盖角度不对"帮不了任何人。

**看不见的关键点跳过而不判错。** 遮挡不该被算成姿势问题。同时统计"测到的规则占多少权重"，比例低于 60% 就宣布无法评分——终端、画面叠加、以及自动模式选哪个体式，三处都遵守。

**不对称体式左右各算一遍取高分。** 你右腿在前时，右侧读法处处吻合、左侧读法处处不通，分差极大，判断很稳。

**用 2D 不用 3D。** MediaPipe 的 z 坐标精度不足以做角度判断。代价是对机位敏感，所以每个体式都声明了推荐机位。

### 时序处理

做实时反馈，不处理时序完全没法用——单帧是噪声：

- 关键点逐个 EMA 平滑（α=0.5），分数再平滑一层（α=0.25）
- 建议至少停留 1.2 秒才换，但**改对的那条立刻消失**
- 建议文字被"冻住"期间，后面的实测数值仍跟着身体走
- 自动识别带迟滞：新体式要连续 8 帧、且高出 6 分以上才切换，否则战士一和战士二会一直互抢

### 渲染

OpenCV 画骨架线条，然后**一次性**转 Pillow 画所有文字——`cv2.putText` 画不了中文。自动搜索系统 CJK 字体（Linux / macOS / Windows 各自路径 + glob 兜底），找不到就整体回退英文，而不是画一屏方块。

## 技术架构

分层的唯一目的：**让"什么算标准体式"这部分完全不依赖摄像头栈**。依赖方向严格单向——上层可以用下层，反过来不行。

```
      ┌─ 纯 Python，无外部依赖，可直接单元测试 ─────────────┐
      │  geometry → landmarks → metrics → checks → poses    │
      │                → evaluator → session                │
      └─────────────────────────────────────────────────────┘
                              ↑
      ┌─ I/O 边界，唯一碰外部世界的一层 ─────────────────────┐
      │  detector(MediaPipe)  render(OpenCV+Pillow)         │
      │  console  voice  cli                                │
      └─────────────────────────────────────────────────────┘
```

数据流是一条直线，没有回环：

```
摄像头 →[detector]→ 33 点 →[landmarks]→ Skeleton →[metrics]→ 数值
     →[checks]→ 单条分数 + 建议 →[evaluator]→ 0-100 + 排序
     →[session]→ 平滑后的稳定状态 →[render / console / voice]→ 输出
```

这个分层直接换来了测试能力：测试全部跑在手写坐标的"火柴人"骨架上，不需要摄像头也不需要 MediaPipe。

## 加一个新体式

在 `yoga_coach/poses.py` 里写一个 `PoseSpec` 加进 `POSES` 就行，**其他文件一行都不用动**：

```python
BOAT = PoseSpec(
    key="boat",
    name=Text("船式", "Boat"),
    sanskrit="Navasana",
    view=Text("摄像头放在身体侧面", "Camera to your side"),
    symmetric=False,
    checks=(
        Check(
            key="knee_straight",
            label=Text("腿伸直", "Legs straight"),
            metric=m.joint_angle("{s}_hip", "{s}_knee", "{s}_ankle"),
            low=160.0, falloff=35.0,
            when_low=Text("小腿再伸直一些", "Straighten the shins"),
            focus=("{s}_knee",),
        ),
        # ...
    ),
)
```

可用的测量在 `yoga_coach/metrics.py`：关节角、与竖直/水平的夹角、左右倾斜、水平/垂直间距、点到直线的偏移。

加完之后跑 `python tools/update_readme.py`，上面的体式表和检查项表会自动补上新体式。

> ⚠️ 加体式时注意"重力方向"：站姿在几何上就是一个完美的平板支撑（肩髋踝三点共线、四肢伸直）。如果新体式和已有体式在几何上相似，需要补一条判别性的检查（比如"身体是否接近水平"），否则自动识别会认错。

## 文档维护

README 里凡是**从代码能推出来的内容**——体式表、每个体式的检查项和目标区间、模块清单、规则条数——都是生成的，不要手改。它们夹在这样的标记之间：

```markdown
<!-- BEGIN GENERATED: poses -->
...这中间的内容会被整块替换...
<!-- END GENERATED: poses -->
```

改完代码后运行：

```bash
python tools/update_readme.py           # 重新生成
python tools/update_readme.py --check   # 只检查，过期则打印 diff 并以 1 退出
```

`tests/test_readme.py` 会跑 `--check`，所以**忘记更新 README 会让测试挂掉**，而不是悄悄发布一份过期文档。

生成器还会在两种情况下直接报错，逼你补文档：

- 新增了模块却没在 `tools/update_readme.py` 的 `MODULE_NOTES` 里写中文说明
- `MODULE_NOTES` 里留着已经删掉的模块

标记之外的散文（技术方案、训练指导的文字部分等）是手写的，生成器不会碰。改了功能记得同步这部分——这一条靠人，也靠 `CLAUDE.md` 里的约定提醒。

## 几句实话

- **这不能替代老师。** 程序看的是二维投影，判断不了脊柱内部的排列、肌肉是否发力、你今天的肩膀能不能到那个位置。它擅长的是抓明显的对位问题——膝盖过脚尖、后腿没蹬直、髋歪了。
- **目标区间是通用课的口令，不是你的个人标准。** 柔韧度、比例、伤病史都会改变什么叫"正确"。分数低不等于做错了。
- **疼就停。** 任何时候都以身体的感觉为准，不要为了把分数拉到 90 而硬压。
- **孕期、伤后康复、有椎间盘或关节问题**，请听医生和线下老师的，别听这个程序的。
- **隐私**：画面全程留在你自己的电脑上，没有上传，除首次下载模型外不联网，也不会默认录制任何东西。
