# Faye_Pivlot

仓库里有两个独立的瑜伽工具，共用一套 MediaPipe 姿态估计底座，但代码互不引用：

| 工具 | 做什么 | 文档 |
|------|--------|------|
| `yoga_grid` | 事后复盘：从练习视频里抓正位帧，拼成九宫格 | 本文以下全部 |
| `yoga_coach` | 实时纠正：摄像头打分并给出具体调整建议 | [docs/yoga_coach.md](docs/yoga_coach.md) |

两者的体式模板是各自独立的（`yoga_grid` 20 个、`yoga_coach` 9 个），目标值和容差
也各自校准——`yoga_grid` 按 2D 投影下的真实练习数据，`yoga_coach` 按通用课口令。
改了一边不会自动影响另一边。

---

## yoga_grid —— 从瑜伽练习视频抓正位帧，拼成九宫格

给一支十几分钟的练习视频，输出一张 3×3 的九宫格图：九个不同体式，每个取该体式做得最到位的那一帧。

```bash
python -m yoga_grid 我的练习.mp4
```

完全离线运行，不上传视频，不调用任何外部 API。

---

## 安装

建议用虚拟环境，别装进系统 Python：

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**Python 版本**：用 3.10 – 3.12。MediaPipe 目前没有 3.13 的 wheel。

**平台差异**（`requirements.txt` 已经把两条线都放开，pip 会自动选）：

| 机器 | 装到的 MediaPipe |
|------|------------------|
| Apple Silicon Mac（M 系列） | 1.0.x |
| Intel Mac | 0.10.x —— 1.0 没有 Intel Mac 的 wheel |
| Linux x86_64 / aarch64 | 1.0.x |
| Windows | 1.0.x |

两条线用的是同一套 tasks API，本项目在 1.0.1 和 0.10.21 上都跑过完整流水线，输出逐项相同。

**Linux 额外需要两个系统图形库**（macOS / Windows 不需要）：

```bash
sudo apt-get install -y libegl1 libgles2
```

首次运行会自动下载约 9 MB 的姿态模型到 `~/.cache/yoga_grid/models/`，之后复用。

装完先跑一遍测试确认环境没问题（不需要视频）：

```bash
python tests/test_grid_geometry.py
```

### Windows 补充

PowerShell 如果拒绝执行 `Activate.ps1`（报 *running scripts is disabled*），二选一：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass   # 只对当前窗口放开
# 或者跳过激活，直接用 venv 里的解释器
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

中文路径（`我的练习.mp4`、输出目录 `瑜伽`）都能正常处理。OpenCV 的文件读写走窄字符 C API，在 Windows 上遇到非 ASCII 路径会静默失败，`compat.py` 已经把这一层绕开：图像用内存编码后由 Python 写字节，视频先试 8.3 短路径、不行再复制一份到临时 ASCII 路径。

## 用法

```bash
# 最简：出一张 2048×2048 的九宫格到 ./out
python -m yoga_grid 练习.mp4

# 指定输出目录和尺寸
python -m yoga_grid 练习.mp4 -o 今天 --size 3000

# 抽帧更密（慢一些，短暂的保持也能抓到）
python -m yoga_grid 练习.mp4 --interval 0.3

# 不想要山式（避免过渡时的站立占掉一格）
python -m yoga_grid 练习.mp4 --exclude mountain

# 看看内置了哪些体式模板
python -m yoga_grid --list-poses

# 导出标准体式库：25 个体式，每个一张带发力要点的对照卡
python -m yoga_grid reference -o 体式库
```

十分钟 1080p 的视频在普通笔记本 CPU 上大约 2–4 分钟，瓶颈是姿态估计。

### 某一帧为什么没被选上

```bash
# 候选文件名形如 0129.25s_c02_triangle_q0.74.jpg，把秒数传给 --at
python -m yoga_grid explain out --at 129.25
```

把两级排序按真实公式重算一遍摊给你看，并直接给结论。一帧落选只可能是两个原因：**它所在的体式簇没进前九**（那一格给了别的体式），或者**簇进了但簇内另一帧分更高**（同一体式只占一格）。输出会说明是哪一种、被谁挤掉的、以及怎么调。

不带 `--at` 就是全局概览：所有体式簇的排名、簇间分和入选情况。

### 改了模板后重新识别（不重跑视频）

```bash
python -m yoga_grid rescore out
```

用**当前**的体式模板，从 `scores.json` 里存好的关键点重跑识别、聚类和选帧，然后重出九宫格、对照图和 `report.md`。

之所以单独有这条路：**姿态估计占整条流水线约 92% 的耗时，而它的产物已经在盘上了。** 实测同一支视频，完整流水线 8.0s、`rescore` 1.1s；十几分钟的视频差距会从「2–4 分钟」缩到「几秒」。改一次模板容差就重跑一遍完整视频，等于把最贵的一步白做一次。

不重算的部分：画质分及其分量、速度、保持段归属——它们不依赖体式模板，重算也不会变，而清晰度这类还需要像素。仍然需要视频的地方只有一处：入选那几张要回读原分辨率像素来出图。

`rescore` 也接受 `--count` / `--cluster-dist` / `--exclude` / `--order` / `--compare` 等参数，所以调这些也不必重跑视频。但改抽帧相关的参数（`--interval`、`--min-hold`、`--work-size`、`--model`）必须重跑——那些决定了有哪些候选帧。

### 按实测分布核对容差

```bash
python tools/calibrate.py out/v1/scores.json out/v2/scores.json
python tools/calibrate.py out/*/scores.json --key pigeon      # 只看一个体式
```

把每个模板每一项检查的**实测分布**（n、中位数、p10~p90、满分比例）和当前的 `target ± tol` 并排列出来，并标出三类问题：

| 判断 | 意思 | 该怎么办 |
|------|------|---------|
| **饱和** | 几乎全部满分，且实测散布远窄于 `tol` | 区间比数据需要的宽，这一项其实没在打分、白占权重 |
| **系统性偏移** | 中位数离 `target` 超过半个 `tol` | 区间取在了错误的位置。照教科书插画取目标值最常犯这个 |
| **常否** | 大量 0 分 | **先怀疑样本被别的体式污染了**，这比「检查项写错了」常见得多，也危险得多——它意味着模板在认领不属于它的帧 |

为什么需要单独一个工具：`report.md` 只写入选那九张里**偏离较多**的项，九张 × 一两项，样本太少，而且只看得到失分的那一头——恰好看不到「全部满分」这种同样需要改的情况。容差是统计量，要按分布调。

两件要紧的事：

- **它逐帧重新识别，不采用 `scores.json` 里的 `pose` 标签。** 那个字段是*簇的结论*（`select` 会把主导体式加给簇里每一帧），拿它当样本等于用别的体式的帧去校准这个体式的容差。
- **多支视频各用 `-o out/日期` 一个目录**，否则 `scores.json` 会被下一次运行覆盖。跨视频的分布才是收紧容差需要的东西——单支视频容易把某一天的状态当成标准，所以样本只来自一支视频时工具会明确提示。

和 `rescore` 配合：`calibrate` 看出该改哪里 → 改 `poses.py` → `python -m yoga_grid rescore out/v1` 秒级看效果。这个工具只读关键点，不碰 cv2 / mediapipe，`requirements-dev.txt` 就够跑。

### 一批体式图片能不能用来校准模板

```bash
python -m yoga_grid images reference_images_pose
```

对目录里每张图跑一遍姿态估计，逐张报出：**检出人体没有**、关键点平均可见度、**人脸关键点置信度**、躯干竖直分量，以及当前 25 个模板给它的最高分和文件名标注的那个体式得几分。文件名和上级目录名都参与识别，`梵文 - English.png`、`下犬式_01.jpg`、按体式分的子目录都认得。

顺带说明这条命令**不能**做什么：识别是写死的几何规则，没有从图片学参数的环节，**放多少图进去都不会让它自己变准**。图片的作用只有两个，都得人来拍板——决定该加哪些模板，以及照着真实取值改模板的目标值和容差。

它能自动下的结论只有一条：**检测不到人体的图确定不可用。** 其余的它只出证据不下判决，因为最容易骗人的恰恰是看起来最像证据的那个数——仓库里 44 张插画的人脸关键点置信度中位数是 1.00，而它们根本没画五官。`visibility` / `presence` 回答的是「这个部位在画面内且没被遮挡」，不是「这里真的有」。

`-o` 指定 JSON 落点（默认 `<目录>/images.json`），里面存的是归一化骨架和每个模板的得分，不含像素——够拿去离线复算模板，也不用把图本身传出去。`--no-json` 只看表格。

哪些素材真能用来校准，判据和踩过的坑写在 [`reference_images/README.md`](reference_images/README.md)。

### 换掉某一格

自动挑的九张不一定都合心意。`candidates/` 里是所有候选帧（文件名带时间、体式、画质分，入选的带 `_PICK`），`scores.json` 里是它们的完整分数。改法：

1. 把不想要那张的 `selected` 改成 `false`；
2. 挑一张想要的，`selected` 改成 `true`，`grid_slot` 设成腾出来的格号（0–8）；
3. 重拼，不用重跑整条流水线：

```bash
python -m yoga_grid grid out
```

## 输出

```
out/
  九宫格_20260828_01.jpg    # 主产物
  report_20260828_01.md     # 复盘：每张的正位分，以及哪个检查项偏了多少
  frames/                   # 入选的九张，原始分辨率的方形裁切
  candidates/               # 所有候选帧缩略图，供人工挑选
  scores.json               # 全部候选的分数与选中标记，可回改后重拼
```

**文件名带日期和当天序号**，所以同一天多跑几次不会互相覆盖：第二次是 `_02`，第三次 `_03`，以此类推。`--compare` 生成的对照图同理。

同一次运行的九宫格、复盘、对照图**共用一个序号**，事后能对上是哪次跑的。序号按目录里当天已有文件推算（取最大值 + 1，不填空洞），所以手动删几张或换个目录跑都不会乱。

`frames/`、`candidates/`、`scores.json` 不带戳，始终是**最近一次**运行的内容 —— 它们是工作材料而不是成品。想让每次运行完全隔离，用 `-o` 指定不同目录就行。

`report.md` 里的正位反馈是这样的：

```
### 3. 战士二式 · 4:12.5

正位分 0.71。偏离较多的项：

- **前膝屈 90°**：实测 118°，目标 92° ± 15（得分 0.21）
- **双臂水平成一线**：实测 19°，目标 0° ± 12（得分 0.73）
```

### 人脸遮挡

默认给露出的人脸盖一个卡通面具，`--no-face-mask` 关掉。

用的是姿态估计已经算出来的面部关键点（鼻、双眼、双耳、嘴角），不额外跑人脸检测模型；从耳距和躯干长度估头宽、从耳线估倾角，所以面具会跟着头部大小和倾斜走。遮挡画在**原始整帧**上而不是裁好的格子上——裁剪会换坐标系，在整帧上做一次，九宫格、单张图、候选缩略图就全都是遮好的，不会漏掉哪条产出。

**判「有没有背对镜头」靠的是左右手性，不是置信度。** 置信度回答的是「这个部位在画面里、没被别的东西挡住吗」，不是「你正对着我吗」——背身帧的面部关键点照样可以是 1.0，所以任何单一置信度门槛都同时犯两种错：挡不住背身帧（一张卡通脸贴在后脑勺上），又会把侧脸误杀（远侧的眼和嘴角被自己的脸挡住、置信度接近 0，平均下来就低于门槛，而脸是露着的——**漏遮才是真正的隐私事故**）。

MediaPipe 的 `left_*` / `right_*` 是**解剖学**左右：面朝镜头时人的左耳出现在画面**右**侧，转过身去就翻到左侧。所以判据取

```
朝向 = cross(躯干朝上方向, 右耳→左耳) / 躯干长度
```

正 = 面朝镜头，负 = 背对镜头。**不能只比 x 大小**：人在体式里会整体旋转（肩倒立、下腰到头朝下），转过来左右在画面上的次序同样颠倒；投到躯干朝上方向的垂线上取叉积，绕视线轴整体旋转时数值不变，所以倒立的正脸仍判成正脸。

正脸约 ±0.30（两耳间距≈0.3 个躯干长），转到正侧面时两耳在画面上重叠、数值过零，符号在那附近没有意义。所以留一条 0.08 的死区，**死区里照样遮**：侧脸是露着的脸。这条取舍是刻意不对称的——按 `0.30 × cos(偏转角)` 折算，遮的范围一直延伸到偏转 105°（已经转过侧面一点），只有更明确的背身才不遮。宁可给侧对镜头的人多盖一张卡通脸，也不漏一张真脸。

置信度仍然用，但只回答「头在不在画面里」（取面部关键点里**最高**的那个，不取平均），以及整个圆完全出框时不必画。

判断部分（该不该遮、遮在哪、遮多大）在 `heads.py` 里，纯几何、不碰 cv2；`faces.py` 只负责落笔。所以 `tests/test_faces.py` 能用手搭的骨架把两个方向的故障都钉住，不需要视频、模型和窗口。

### 标准体式对照（可选，默认关闭）

加 `--compare` 会额外生成 `标准对照图.jpg`：一行一个体式，左边你的画面、中间标准线稿、右边偏差项与发力要点。

**默认不出**——线稿是「有体积的火柴人」，识别得出体式但风格偏简，未必人人受用。功能保留着，想看随时开。

**标准图是用打分模板的目标几何渲染的，不是外部照片。** 这既避开版权，更重要的是保证对照有意义：图里的角度就是模板的目标值，所以「你和标准图的差距」和「正位分扣掉的分」是同一件事。换成一张来源不明的照片，它的角度未必等于模板目标，对照反而会误导。

`python -m yoga_grid reference` 可以单独导出整个体式库。库里每张卡的发力要点是**锚定到部位**的——因为图是生成的，每个关节坐标已知，所以每条要点都有引线指向它说的那个部位，加一个箭头标发力方向。

发力要点是通用教学口令，不针对个人，不能替代老师指导。

## 工作原理

四层过滤，从最可靠的信号开始。

**① 保持段检测** —— 正位几乎只出现在体式稳住的那几秒，过渡动作都在快速移动。按 0.5 秒抽帧后，用关键点的移动速度找出低速窗口。这是最可靠的一层：判断「动没动」比判断「姿势对不对」稳得多，能把上千帧砍到几十段，几乎不误杀。

速度由两部分相加：**姿态速度**（髋心归一化后主干关键点的位移，反映肢体构型变化）和**整体速度**（髋中点自身的位移，反映人在移动）。只算前者，「保持同一姿势往后退一步」会被误判为静止；只算后者，原地挥臂会被误判为静止。

阈值默认自适应——取速度分布的 30 分位数，因为流瑜伽和阴瑜伽的节奏差异很大，固定阈值不通用。

**② 画质筛选** —— 每个保持段内挑关键点置信度高、人体完整入画、不模糊的帧。清晰度用同一视频内的**分位排名**而非拉普拉斯方差绝对值，后者随分辨率和光线大幅漂移，没有可比性。

**③ 体式识别与正位打分** —— 一组基于关节角度的规则模板（见下）。每项检查测一个几何量并和目标值比对，误差在容差内给满分、超出后线性衰减到零。

模板还带一个**躯干朝向门槛**：脊柱方向的竖直分量（+1 直立、0 水平、−1 倒置）必须落在该体式允许的区间内，否则整个模板分乘以一个衰减系数直至归零。这一层不可省——判断「竖直」的常规做法要取绝对值，分不出直立和倒立，会把肩倒立判成山式。

**④ 聚类去重与选帧** —— 按归一化骨架距离做平均连接层次聚类，然后**先拆再投票再合并**：

1. **拆** —— 骨架距离只保证「这些帧姿势彼此接近」，不保证是同一个体式。俯卧类体式在默认 `--cluster-dist 0.35` 下尤其糊：真实视频里 331 个候选聚出 13 簇，其中**一簇 159 帧横跨 1.7~31.9 分钟、含 6 个体式**（直臂斜板 115、四柱支撑式 22、半神猴式 9、上犬式 6、反板式 4、婴儿式 3）。所以按逐帧识别结果把有确信分歧的簇拆开。识别不出的帧在明显是少数时并入最大的那一份（擦边没过门槛的帧确实和主导体式接近），多于最大那一份时自己成簇——否则就是拿少数派的标签盖多数派。
2. **投票** —— 拆完簇内本就同一个体式了，再定主导体式并给每帧算可比的正位分。顺序反了的后果不只是少几个格子：主导体式的标签会盖到全簇，于是 `report.md` 拿直臂斜板的目标值去点评一个四柱支撑式，写出「直臂斜板，身体成一直线 118°，目标 178±10」这种**针对错误体式**的建议。认不出来只是没帮上忙，指着四柱式说你的平板不直是在帮倒忙。
3. **合并** —— 把主导体式相同的碎片重新聚拢（机位角度会把同一体式拆成两簇，不合并的话九宫格里会出现两个下犬式）。左右版本的同一体式默认算同一个（`--mirror-distinct` 可分开）。

然后**两级排序，刻意用不同依据**：

- **簇内**（同一体式挑哪一帧）按正位分——同体式共用一套模板，分数可比；
- **簇间**（哪九个体式进九宫格）按画质分与保持时长，**不用**正位分。不同体式的模板宽严不一，横向比较会系统性偏袒容差松的体式，还会把没识别出体式的帧一律挤掉。

体式种类不足九个时，用已入选体式的另一次保持补位。间隔要求从 8 秒起逐级放宽直到填满 —— 3×3 里空一格看起来就是坏的，宁可补一张时间上近一些的。实际用了多大间隔会标在 `report.md` 和对照图里。

### 三个板式的命名

三个体式在中文里名字只差一个字，而它们的几何差别很大，所以按练习者的叫法固定下来：

| 英文 | 中文全名（模板标签） | 简称 | 几何特征 |
|------|------------------|------|---------|
| forearm plank | **前臂平板** | 平板 | 前臂整条贴地，屈肘约 100° |
| high plank | **直臂斜板**（亦称高位平板） | 斜板 | 手臂伸直，双手撑地 |
| side plank | **侧板式** | 侧板 | 身体侧转，一手撑地一手朝天 |

前两者靠「腕比肘低多少」分开——手撑地时低半条小臂（0.42~0.50），前臂贴地时肘腕同高（实测 -0.06~0.00）。`yoga_coach` 的 `plank` 模板是 Phalakasana，同属直臂那一种，名字已经对齐。

**最后五个的目标值取自真实练习实测，不是插画。** 它们是 2026-08 从两支练习视频里挖出来的 —— 此前一直在被邻近模板认走（幻椅式→新月式、压脚背→树式整簇 16 帧、四足跪姿→直臂斜板 46 帧、展背式→站立前屈式），补门槛只让它们回到「未识别」，补模板才是正解。标准骨架也照同一批数据搭，每具的 docstring 里写着实测区间。

**识别不出的体式不会被丢掉**——它们照样按画质和保持稳定性参与九宫格竞争，只是标签显示「未识别体式」、没有正位分。所以练了模板之外的体式也不会漏。

不想要它们占格子就加 `--skip-unrecognized`。注意 **`--exclude` 排除的是体式 key，不是帧**：排掉某个 key 只是让那个模板不再认领这些帧，帧本身照旧参与竞争、照旧可能入选（标签变成「未识别体式」）。这两件事分开是有意的，但曾经害人——`--exclude unknown` 看起来像在做后者，实际什么也没发生。现在 `--exclude` 会校验 key，拼错直接报错并列出可用的 key。

加新体式就是在 `poses.py` 的 `TEMPLATES` 里加一条：几项 `Check`（测量函数、目标值、容差、权重）加一个 `spine_up` 朝向区间。`Check` 的测量函数通过 `PoseView` 访问关键点，`s_` 前缀表示主侧、`o_` 表示另一侧，同一个模板会自动左右各试一遍取高分，不必为左右各写一份。

加模板时**必须同时在 `yoga_grid/reference.py` 里加一具标准骨架和一组发力要点**，测试会强制这一点。原因见下面「模板互相误判」一节 —— 模板集变大后，主要风险不是认不出，而是新模板把别的体式认走。

除 `Check` 之外还有 `Gate`（`poses.Gate`）：**这个体式的定义性特征**，不满足就不是这个体式。两者区别不在严格程度而在作用方式——`Check` 按权重扣分，一项归零最多损失它那份权重；`Gate` 是乘在总分上的系数，归零则整个模板归零。什么该做成 `Gate`：把这个体式和「别的动作恰好也满足的那堆检查」区分开的那一条。`spine_up` 是同一机制的先例，只是每个模板都有、所以单独成字段。

现在 17 个模板带门槛，每一条都是真实视频里的一次误判换来的，见「模板互相误判」。写门槛时的三条经验：

- **门槛要挑「有 / 没有」那种判据，不是把某个容差改严。** 树式的「支撑腿必须伸直」「抬起脚必须离地」是定义；山式和「随意站着」之间**没有**这种判据（差别全在程度上），所以山式是唯一一个没有门槛的模板，靠抬高 `min_score` 和取两膝中较屈的那个撑着——`tests/test_grid_templates.py` 里为它单列了一个测试说明这件事。
- **别把评分项本身做成门槛。** 塌腰的直臂斜板仍然是直臂斜板，塌腰恰恰是要反馈给练习者的东西；把「身体成一直线」做成门槛会把这条建议整个静音。直臂斜板的门槛是「膝盖不能落地」——它区分的是「差的直臂斜板」和「根本不是直臂斜板」。
- **`Gate` 的作用方式必须落盘。** `gate` 系数和 `orientation` 一样乘在总分上，两者都写进 `scores.json`；`report.md` 在门槛压低了分数时会先说明「这一帧可能不是这个体式」。少了这一步，一个被门槛压到 0.2 的分数看起来和「各项都做得差」一模一样，而两者该做的事完全相反。

## 参数调优

| 症状 | 调这个 |
|------|--------|
| 找不到保持段 | `--min-hold 0.5`，或 `--vel-thresh 0.6` 放宽静止判定 |
| 短暂的保持被漏掉 | `--interval 0.3` 抽密一点 |
| 体式种类偏少、总在补位 | `--cluster-dist 0.25` 分得更细 |
| 同一体式占了好几格 | `--cluster-dist 0.45`，或确认 `--no-merge-same-pose` 没开 |
| 过渡时的站立占了格子 | `--exclude mountain` |
| 某一格是识别不出的动作 | `--skip-unrecognized`（`--exclude` 排 key 不排帧） |
| 裁图切到了头或脚 | 默认就不会切；若用了 `--pad-mode crop`，换回 `blur` |
| 想留人体周围更多环境 | `--pad 1.6` |
| 标签是英文 | 系统缺中文字体，用 `--font /path/to/字体.ttf` 指定 |
| 不想遮脸 | `--no-face-mask` |
| 想要标准体式对照图 | `--compare` |
| 想更准（慢一倍） | `--model heavy` |

## 局限

- **角度都在图像平面（2D 投影）上算。** 练习者明显斜对镜头时，投影角度会偏离真实解剖角度，正位分偏低。固定机位、身体大致与镜头平面平行时最准。
- **模板的容差是按真实练习校准的，不是按教科书插画。** 这一点吃过教训：最初的标准骨架照插画搭，三角伸展式和侧角伸展式的躯干都偏立（竖直分量 0.57 / 0.50），而真实练习中躯干常沉到接近水平（实测 -0.01 / +0.10）。结果是**正确的模板先把自己排除在朝向门槛之外**，再让别的体式抢走——三角伸展式被判成战士三式、侧角伸展式被判成半神猴式。容差已按真实数据放宽。加新体式时请照此：先想清楚该动作在真人身上的取值范围，别只照插画，并用 `tools/calibrate.py`（见下）拿实测分布核对一遍。
- **模板覆盖二十四个体式，够不够只有拿你自己的练习跑一遍才知道。** 一次实测的教训：模板集从 20 个扩到 24 个之前，两支真实练习视频（38 分钟 + 16 分钟）的逐帧未覆盖率是 **28% 和 14%**——而缺的不是冷门体式，恰恰是高频的那些（四足跪姿在一支视频里就有 46 帧）。补上四个之后降到 **2% 和 12%**，而 12% 那部分逐帧查过：全是练习者趴着看手机（16 帧）和随意站着（4 帧），**不是体式**。所以「未覆盖率」既是模板集的体检，也是「这段视频里有多少不是在练瑜伽」的度量，看具体是哪些帧才有意义——`tools/calibrate.py` 和 `python -m yoga_grid explain` 都能拿到。
- **未覆盖的帧宁可认不出，不要认错。** 它们照样参与九宫格竞争（标签「未识别体式」），不想要就加 `--skip-unrecognized`。反面教材见「库里没有的体式」一节：补门槛之前，这些帧被邻近模板轮流认走，写出的是**针对错误体式**的纠正建议。
- **正位分衡量的是几何对位，不是安全或体感。** 它不知道你的柔韧度、代偿或旧伤，别拿它当教学替代。
- **侧面机位下，远侧那半边身体的关键点是猜的，规则层看不出来。** 实测某支 38 分钟的视频（机位固定在身体侧面）：右肘置信度中位数 0.447、右膝 0.315，80% 的帧右膝低于 0.5；另一支视频练习者转了个方向，于是变成左侧不可信。**MediaPipe 对被遮挡的肢体倾向于照着可见那一侧复制**，所以数值看着合理，而 `visibility` 是唯一能看出它是猜的地方。

  影响的是所有把左右两侧合起来算的量：`_legs_extended` 把测量值和猜测值一起平均；`_worse_leg_extended` 取 min，实测有 49% 的帧读到的正是那个猜出来的膝。它们目前仍给出正确结果，但那是因为「照着可见那侧复制」恰好和真实情况一致——**一条腿真的屈着、而且正好是被挡住的那条**时就会失效。

  **已做的部分：把这件事说出来。** `PoseView` 现在可以拿到置信度，每项检查记下「我用到的关键点里最低的那个」（`CheckResult.confidence`，也写进 `scores.json`）。`report.md` 会点明哪些项读到了被遮挡的关键点，并把「看着达标其实没测准」的项单独列一行；`tools/calibrate.py` 多一列「遮挡」，是这一项有多少帧读到低置信度关键点。实测一眼就看出问题：山式的「双腿伸直」有 **91%** 的帧读到被遮挡的膝，而它是山式权重最高、容差最紧的一项。

  **刻意没做的部分：不改分数。** 把低置信度的一侧排除掉，实测在 493 帧上改变 **0 个**识别结果、**0 个**分数（>0.05），而且有反例——用户确认正确的那帧侧角伸展式，被遮挡的前腿膝角读 113° 是**对的**，排除它等于丢掉一个正确测量。缺失的信息不是任何聚合策略能补回来的；能做的是**知道自己不知道**。
- 画面里多人时取外框最大的那个，未必总是练习者本人。
- **遮脸的朝向判据依赖 MediaPipe 自己给出的解剖学左右。** 正侧面附近两耳在画面上重合，模型的左右标签本身就可能互换——这一带按「宁可多遮」处理，落在死区里一律遮。反过来，脸被手臂或垫子完全挡住的帧（婴儿式、双手合十挡脸）照样会盖一张卡通脸：难看，但不是隐私问题。

## 关于视觉模型打分

这一版是纯离线的规则实现。原方案里还有一步「用 Claude 视觉对候选帧打分」——它通用性更强（不必穷举体式模板），也能给出文字化的正位反馈。接入点在 `score.py`：`Candidate.alignment` 是唯一被下游消费的正位分字段，`select.py` 的 `_assign_alignment` 是它的唯一写入处。换成视觉模型打分只需替换这一处，选帧、聚类、拼图都不用动。

## 测试

```bash
python -m pytest tests/ -q                 # 两个工具的测试都在这里
python tests/test_grid_geometry.py         # 只跑 yoga_grid 的几何部分
```

`tests/` 目录是两个工具共用的，文件名前缀区分归属：`test_grid_*` 属于
`yoga_grid`，其余属于 `yoga_coach`。两边的测试都不需要 MediaPipe，
`pip install -r requirements-dev.txt` 就够跑。

`test_grid_geometry.py` 覆盖角度计算、归一化的平移/尺度不变性、镜像置换、朝向门槛、聚类分组与**簇内拆分**、打分分量、`tools/calibrate.py` 的读盘与取样，以及跨平台回归（requirements.txt 纯 ASCII、Unicode 路径写图）。

`test_grid_faces.py` 钉住**遮脸判断**：正脸、背身、中间的侧脸各一档，加上整体旋转不变性（倒立的正脸还是正脸）和两个方向的原始故障——远侧关键点被挡住时不许漏遮、面部置信度全 1.0 的背身帧不许误遮。骨架同样是手搭的，不需要 cv2。

`test_grid_templates.py` 是**模板区分度网**：遍历 `yoga_grid/reference.py` 里每个体式的标准骨架，断言最高分模板就是它自己；另外检查每个体式都有发力要点、每个要点的锚点都能解析、20 张线稿与对照卡都能渲染。它还带两组按**真实练习实测不变量**手搭的骨架：5 具负例（库里没有模板的，断言没有任何模板认领，且拦住它们的是定义性门槛而不是「刚好没过 `min_score`」——后者靠的是分数差，容差一动就会翻过去），以及 4 具现在有模板的（断言认出来、而且认成对的那一个）。

后一组比标准骨架检验强得多：**标准骨架是照目标值搭的，实测骨架不是。** 目标值取偏了位置，标准骨架照样满分，只有实测骨架会红。同一节还钉住「新模板不能反过来把老体式抢走」的四对相邻关系——补模板的风险和补门槛正好相反：门槛把帧推给邻居，模板把邻居的帧抢过来。

### 模板互相误判

模板集越大，主要风险不是「认不出」，而是 **A 体式被 B 的模板认走**。这类错误在真实视频上已经发生过多次，每一条都是先出错、再回头补判据：

| 错误 | 缺的判据 |
|------|----------|
| 旋转 180° 的身体判成山式 | 有符号的躯干朝向门槛（`vert` 取了绝对值，分不出直立和倒立） |
| 上犬式被三角伸展式认走 | 站姿约束（两者躯干竖直分量都在 0.5 附近，朝向门槛分不开） |
| 直臂斜板在战士三式上拿 0.8 | 站姿约束 + 提高「支撑腿竖直」权重 |
| 双臂上举的战士一式判成战士二式 | 「双臂与肩同高」（上举时两腕连线同样水平） |
| 侧板式被直臂斜板认走 | 手部检查取双手中较低者（只看主侧会被撑地那只手蒙混） |
| 反板式被直臂斜板认走 | 头部朝向这一对称判据（2D 剪影近乎镜像） |
| 三角伸展式被判成战士三式 | 「抬起脚远高于支撑脚」——战士三式单脚离地（约 2.0），三角伸展式双脚在地（约 0.0）；且三角伸展式的躯干倾角容差原先按插画取，排除了深度版本 |
| 侧角伸展式被判成半神猴式 | 半神猴式缺「髋位低（跪姿）」——跪姿双踝只在髋下 0.4，站姿弓步是 1.0~1.2 |
| 金字塔式被判成站立前屈式 | 站立前屈式缺「双脚并拢」——并拢时两踝水平距 0.02~0.35，金字塔式前后错开是 0.58~1.53。真实视频里一个 22 帧的簇混了两个体式，其中 19 帧是金字塔式 |
| 蹲姿被鸽子式认走 0.77，排除鸽子式后又被半神猴式认走 0.71 | 两个模板各加一条 `Gate`：伸直的那条腿必须真的伸直（区间比同名 `Check` 宽得多——门槛只回答「是不是这个体式」） |
| 用户确认正确的侧角伸展式反被半神猴式认走 0.99 | 「后膝必须跪在地面上」（`_back_ankle_below_knee`）。非对称模板左右各试一遍，于是站姿弓步把「屈着的前膝」当成了「跪着的后膝」——两条腿的**角度**门槛同时被满足。膝角分不出那条腿在不在地上 |
| **完全平直的身体被上犬式认走 0.98**，同一个姿势在九宫格里出现了两次 | 上犬式的「躯干后弯」原先是 150±22 / slack 38——衰减到 0 的位置在 210°，于是 175.5° 的平直身体还能拿 0.91 分。收到 145±18 / slack 12，并把后弯做成门槛。实测唯一一帧真上犬式读 138.7°，被误认的直臂斜板是 175.5~179.1°，中间空着 37° |
| **四足跪姿单腿后伸被六个模板依次认领** | 见下节末尾——它是「一个高频动作缺模板会污染整个几何邻域」最完整的例子 |
| **前臂平板（小臂贴地）被四柱支撑式认走 0.90~1.00** | 两者肘角都在 90~100°、身体都成一直线、都是俯卧，「屈肘约 90°」分不开它们。分水岭是腕比肘低多少：手撑地时低半条小臂（标准四柱 0.43），小臂贴地时肘腕同高（实测 -0.06~0.00）。补了 `forearm_plank` 模板，两边各加一条方向相反的门槛。**这一条是逐格核对发现不了的**——那 18 帧没进九宫格 |

最后一条和其它几条**性质不同**，值得单列：蹲姿（Malasana）在模板集里根本没有对应模板。前面几条都是「A 被 B 认走」，补判据补在 A 或 B 身上就行；没有模板的动作补不到它自己身上，只能给被它蒙混的模板加门槛，而且排掉一个模板它就换下一个最近的——两次误判是同一帧。

它也暴露了这张网原先的盲区：**只测模板互相之间，从不测「库里没有的体式」**。真实练习里模板外的动作远多于模板内的，所以负例才是常态。加模板时也请加负例。

### 库里没有的体式：一次逐格核对的结果

2026-08 跑了两支真实练习视频（38 分钟 + 16 分钟，共 493 个候选帧），逐格核对九宫格后，18 张里有 6 张标错——**全部**是「库里没有这个体式，它去挤了几何上最像的模板」。和蹲姿同一个结构，只是一次来了七个：

| 实际是什么 | 曾被认成 | 唯一正确否决它的那一项 | 补的门槛 |
|-----------|---------|--------------------|---------|
| 幻椅式（双脚并拢、双膝都屈） | 新月式 0.97 | 无——「前膝屈 90°」和「后膝屈曲跪地」被两条都屈的膝同时满足 | 新月式、战士一式：双脚必须前后分开（实测弓步 1.93~2.04，幻椅式 0.01~0.07） |
| 压脚背（跪坐脚跟上、手在胸前） | 树式 0.78，**整簇 16 帧** | 支撑腿伸直 | 树式：支撑腿必须伸直 + 抬起脚必须离地 |
| 四足跪姿/桌面式，46 帧 | 直臂斜板 → 四柱支撑式 → 桥式 → 婴儿式 | 身体成一直线（实测 126~146°） | 直臂斜板、四柱支撑式：膝盖不能落地（实测跪姿 0.87~0.98，平板 0.27~0.45）；桥式：膝不能压在髋下方；婴儿式：躯干必须折叠贴腿 |
| 站立伸展（半程前屈），18 帧 | 站立前屈式 → 金字塔式 → 下犬式 → 战士三式 | 躯干向下倒垂（实测 -0.35~-0.49，满程是 -0.85 上下） | 站立前屈式：躯干必须倒垂过半；金字塔式：双脚必须前后错开；下犬式：双腿必须向后斜展；战士三式：抬起脚必须离地 |
| 俯卧撑起上身**看手机** | 鸽子式 0.83 → 半神猴式 → 上犬式 → 反板式 | 前腿屈膝外旋 / 双臂伸直（双肘折到 8°） | 鸽子式：前腿必须屈膝；上犬式、反板式：双臂必须伸直 |
| 随意站着（手臂没下垂，两膝 171°/148°） | 山式 0.87 → 树式 | 双腿伸直——但取的是**均值**，159° 还能拿 0.52 分 | 改取两膝中较屈的那个（`_worse_leg_extended`）、权重提到最高、衰减区收窄；树式：抬起脚必须离地 |
| 双手撑地的低弓步（过渡） | 鸽子式 0.92 → 半神猴式 → 反板式 → 侧角伸展式 → 上犬式 | 各模板各有一项，都被投票淹没 | 鸽子式：前小腿必须横过身前；半神猴式：后膝必须跪在地面上；侧角伸展式：后腿必须伸直；上犬式：双腿必须贴地后展 |

**其中四个后来补成了正式模板**（`chair` / `toe_squat` / `table_top` / `ardha_uttanasana`），目标值就取自上表那些实测区间。补完之后 v1 的未覆盖率从 28% 掉到 2%，九宫格九格全部有名有姓；v2 剩下的 12% 逐帧查过，全是趴着看手机和随意站着。

另外三个刻意不补：

- **蹲姿**和压脚背差别太小（都是两腿都折着、躯干竖直、双脚并拢，只差折的程度和髋的高度），补上会让两者互抢。压脚背的「必须深度屈膝」门槛上界因此收到 52°，专为把 64° 的蹲姿挡在外面。
- **随意站着**、**趴着看手机**不是体式。
- **双手撑地的低弓步**是过渡动作，而且实测那 13 帧分成两种形状（前膝 79~86 / 后膝 131~139，与前膝 117~120 / 后膝 96~99），一个模板盖不住；认出来也不会改变选帧——簇间排序用的是画质和保持时长，不是正位分。

**四足跪姿单腿后伸**（鸟狗式的腿那一半）值得单独说，它是这批里最难拦的一个，被**六个**模板依次认领：

```
半神猴式 1.00 → 直臂斜板 0.93 → 侧角伸展式 0.72 → 上犬式 0.72 → 侧板式 0.67 → 未识别（最高分 0.48，门槛 0.64）
```

每一轮补的都是那个模板**真正的**定义性特征，不是为它量身定做的补丁：

| 模板 | 补的门槛 | 为什么它原先拦不住 |
|------|---------|------------------|
| 半神猴式 | 伸直的腿必须伸向**前**方 | 它一条腿伸直、一条跪着、小腿贴地，四条门槛全满足；差别只在腿伸向躯干的哪一侧（投影 -1.55 对真实的 +1.50） |
| 直臂斜板 | 膝盖不能落地——改取**两膝中更低的那个** | `_knee_drop` 取中点，一膝落地（0.92）一膝抬起（0.2）被抵消成 0.57，恰好钻过 0.60 的上界 |
| 侧角伸展式 | 必须是站姿 | `_feet_below_hips` 的注释早就写着站姿体式必须显式要求站姿，但它一直只是评分项 |
| 上犬式 | 双腿必须都伸直 | 跪着那条腿 88°，而「双腿伸直后展」取均值 |
| 侧板式 | 上手不能撑地 | 「上臂向上伸展」的注释写着这是与直臂斜板的区别，但它只有 2.0 权重、归零只扣 19% |

四条里有三条是「本该是门槛的评分项」，一条是「本该取 max 的均值」。**如果一个模板的注释里写着「这一项是与 X 的区别」，那它大概就该是门槛而不是评分项**——这是这一轮最可迁移的一条。

这一轮学到三件事，比七条门槛本身更值得记：

1. **补门槛会把误判推给邻居，得顺着推下去补完。** 上表第三、四、七行的箭头就是这个：压脚背用了 2 轮，站立伸展 4 轮，低弓步 5 轮。所以负例测试断言的是**「没有任何模板认领它」**，而不是「某个模板拒绝了它」——后者会漏掉下一站。分数每一轮都在降（0.92 → 0.85 → 0.73 → 0.72 → 0.70 → 未识别），是收敛的。
2. **按实测放宽一项容差，要先问它是不是还兼着判别的职责。** 下犬式「双腿向后斜展」的目标照实测从 45° 下调到 35° 之后，站立伸展在这一项上从 0 分变成 0.65 分，总分越过了门槛。判别那一半必须移到门槛上，别指望一个区间同时干两件事。
3. **「取均值」这个坑已经踩了四次，看到就该警惕。** `_lowest_wrist_drop` 取 min（侧板式一手朝天一手撑地，均值会抵消）、`_worse_leg_extended` 取 min（一腿直一腿屈，均值 159° 还能算「双腿伸直」）、`_lower_knee_drop` / `_higher_knee_drop` 取 max/min（一膝落地一膝抬起，两膝中点算出 0.57，恰好钻过直臂斜板「膝盖不能落地」0.60 的上界）。**凡是问「是不是两边都……」或「有没有哪一边……」的量，均值一定是错的聚合方式**——前者取最差的那边，后者取最极端的那边。
4. **补模板的风险和补门槛正好相反，得两头都测。** 门槛把帧推给邻居（上面第 1 条），模板把邻居的帧抢过来。所以加模板时除了「新骨架认得出自己」，还要断言**老体式的标准骨架没被新模板抢走**——`test_grid_templates.py` 里钉了四对（幻椅式↔新月式/山式、压脚背↔树式/婴儿式、四足跪姿↔直臂斜板/四柱式、展背式↔站立前屈式/金字塔式）。
5. **样本被污染时量出来的「重叠」是假的。** 半神猴式的「髋位低（跪姿）」曾被判定为「已经和侧角伸展式重叠、区分不动了」，依据是实测 0.61~0.94 对 0.74~1.07。但那 0.74~0.89 是混进侧角伸展式样本里的低弓步；剔掉之后真实区间是 0.80~0.94 对 0.96~1.07，**不重叠**。`tools/calibrate.py` 会把「大量 0 分」标成「常否」并提示优先怀疑样本污染，就是为了这个。

`test_grid_templates.py` 把这些判据全部钉死，调容差或加模板时若破坏任何一对区分，测试会立刻指出被谁抢走了。所有骨架都是手搭的，不依赖视频或模型文件。
