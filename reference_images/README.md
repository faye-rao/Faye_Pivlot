# reference_images —— 体式参考素材库

这是一个**会持续增长、来源混杂**的素材目录。能不能用来做什么**取决于具体是哪一批**，
不要对整个目录一概而论。下面先分述现有内容，再给新素材的判断方法。

命名统一为 `梵文 - English.<扩展名>`。

**扩展名不可信，别拿它判断格式。** Yogaru 那 44 张全都以 `.png` 结尾，实际是
**WebP**——抓图时后缀取自 URL，而 Squarespace 通过 `?format=2500w` 返回的是 WebP。
没有改名，因为 Pillow 和 OpenCV 都按文件头识别格式，读取不受影响，48 张改名换来的
只是好看。但任何按扩展名过滤或分派的代码都会踩到，**要判断格式请读文件头**：
JPEG 是 `FF D8 FF`，PNG 是 `89 50 4E 47`，WebP 是 `RIFF....WEBP`。

## 目录里现在有什么

**44 张 Yogaru 插画（`©YOGARU`，商业教学产品）。** 来自
[Yogaru](https://www.yogaru.ie) 的 Pose breakdowns 系列，文件名沿用其文章标题。
**不是本项目的作品**，也不是真人照片——是扁平剪影插画：躯干一块实色，手脚抽象色块，
肢体互相融合，头部没有五官。

这一批**不能用来校准模板容差**，理由见下节；也**不能放进程序输出**，理由见再下节。
它们的价值是给人看：决定该加哪些模板，以及自己写发力要点时做参考。

**少数手工补的图，来源与画风各异。** Yogaru 那个系列没覆盖的体式（半神猴式、
鸽子式、反板式），以及 `Vasisthasana - Side Plank (right).png` —— 后者是全彩卡通
人物画风，和 Yogaru 的剪影完全不同来源，也没有水印。可用性按下面的方法逐张判断，
不因为是手工补的就默认可用。

同一体式可以有多张图（侧板式现在就有两张）。**请在文件名里体现区别**，例如括号里
标左右或机位，否则事后分不清哪张是哪张。

## 两个独立的问题，别混为一谈

不要靠肉眼判断，跑一遍姿态估计看结果：

```bash
python -m yoga_grid images 你的目录
```

逐张报出检出情况、关键点可见度、人脸置信度、躯干竖直分量，以及当前模板给它的
最高分和文件名标注的那个体式得几分。

判断素材能不能用，要分开问两件事。它们的答案不一定一致，混在一起会得出错误结论
（这份文档的前一版就混了）：

**问题一：姿态估计找得到人体吗。** 这是**逐张而定的，和画风无关**。实测：Yogaru
那 44 张剪影里 **34 张检测得到**，10 张完全找不到人——其中包括
`Tadasana - Mountain`，最简单的直立站姿。而侧板式在两种画风下都成功，卡通那张甚至
在侧板式模板上拿到 1.00、剪影那张 0.94。所以「剪影/插画认不出」是错的说法。

**问题二：即使检测得到，读数可信吗。** 这里有一个必须自己动手验的陷阱：这批插画的
**面部关键点置信度中位数是 1.00，而它们根本没画脸**。`visibility` / `presence`
回答的是「这个部位在画面内且没被遮挡」，不是「这里真的有」。所以高置信度**不等于**
位置正确。

验法：挑一个**你能独立确认真值**的关键点去反驳它。脸最好用——一张图有没有画脸，
看一眼就定了。

## 检测成功也不代表能用来校准容差

这是第三件事，和上面两个问题都独立，而且它是**校准这个用途的决定性理由**。

插画画的是「体式应该长什么样」的理想化印象，真人做同一个体式时关节角度常常离那个
印象很远。所以一张检测得完美的插画，给你的仍然是理想值而不是真实分布——**而容差
要校准的正是分布**。

## 为什么插画会把一个修好的 bug 装回来

`yoga_grid/README.md` 的「局限」一节记着一条已经付出过代价的教训：最初的标准骨架
照插画搭，三角伸展式和侧角伸展式的躯干竖直分量取到 0.57 / 0.50，而真实练习实测是
-0.01 / +0.10，结果**正确的模板先把自己排除在朝向门槛之外**，再被别的体式抢走。
容差后来是按真实练习数据重新放宽的。

Yogaru 那张 Trikonasana 就是现成的例子：图里躯干画成接近竖直，正是被真实数据推翻的
那个值。**画得越"标准"，这个偏差越大**——理想化本来就是插画的目的。

`python -m yoga_grid images reference_images` 里还有一个更直白的迹象：检出的 37 张
里有 11 张拿到 **1.00 满分**，而其中 2 张**满分给错了体式**——

| 图 | 满分判成 | 实情 |
|----|----------|------|
| `Ashta Chandrasana` 新月式 | 战士一式 1.00 | 新月式模板只给它 0.87 |
| `Parivrtta Ashta Chandrasana` 扭转新月式 | 三角伸展式 1.00 | 扭转新月式没有模板 |

一张扭转新月的插画在三角伸展式模板上一分不扣，说明这些图的关节角度落点是
**画法惯例**，不是那个体式的解剖特征。拿它校准等于把画法抄进模板。

（补了幻椅式、前臂平板等模板之后，原先四张里有两张各自归位：`Utkatasana` 现在
正确地判成幻椅式 1.00，`Utthan Pristhasana` 从「四柱支撑式 1.00」落到「前臂平板
0.87」。**补模板确实能消掉一部分满分误判**——但消不掉的这两张说明问题不止于覆盖率。）

## 第二批素材：另一个来源，同样的结论

用户后来自己补了一批 22 张（`reference_images_pose/`，不在仓库里），来源和
Yogaru 那批不同，同样跑了一遍 `yoga_grid images`：

- **22 张里 11 张检测不到人体**，包括站立前屈式、四柱支撑式、上犬式、下犬式
  这些最简单的 —— 比例比 Yogaru 那批（48 张里 11 张）还差一倍。
- 剩下 11 张里，**凡是模板覆盖到的体式，没有一张能用**：`Anjaneyasana` 的
  新月式模板只给 0.20（排第 12），`Setu Bandhasana` 的桥式模板给 **0.00**。
- 最说明问题的一张：`Kapotasana.jpg`，用户看图确认里面是**四柱支撑式**，
  而姿态估计给出的骨架是**躯干竖直分量 +0.96、一腿折叠一腿侧伸、双臂关键点
  置信度 0.07~0.14**（等于没检测到手臂）。四柱支撑式躯干接近水平、双臂承重，
  两者无法调和。**文件名、图里的体式、检测出的骨架，三者互相矛盾。**

操作上的经验（两批素材，样本不多，当经验用不当定论）：**先看整批的检出率，
再看单张。** 这两批都在第一步就垮了，逐张分析的功夫是白费的。

不过整批不能用，不等于每一张都没信息。**这批里检测质量最好的一张反而挖出了一个
模板缺口**：`Ardha Chandrasana.jpg`（半月式）平均可见度 0.99、四肢关键点置信度
0.95~1.00，骨架读出来是躯干水平、一臂朝天一臂触地（两腕竖直相距 2.4 个躯干长）、
上侧腿完全伸直 —— 半月式的教科书形状，用户看图确认过。而模板给它：

    半神猴式 0.85   三角伸展式 0.74   反板式 0.66   ...   新月式 0.00

**0.85 高过识别门槛**，所以真实视频里做半月式会被标成半神猴式。半月式目前没有
模板，补法有两条：加一个半月式模板，或给半神猴式加一条判别性门槛（后腿是撑在
地上还是抬在空中）。记在这里，等模板那一轮一起做。

所以判断素材能不能用来校准，标准不是「画得准不准」，也不是「检测得到没有」，而是
**它记录的是真人的一次练习，还是某人对这个体式的印象**。

要校准容差，走真人练习视频这条路：跑一次 `python -m yoga_grid 练习.mp4`，关键点会
存进 `scores.json`，之后 `rescore` 可以秒级重算，改一次容差不必重跑视频。多支视频
各用 `-o out/日期` 一个目录，否则 `scores.json` 会被下一次运行覆盖——而跨视频的
分布正是收紧容差需要的东西，单支视频容易把某一天的状态当成标准。

## 第三方素材不要放进程序的输出

`yoga_grid --compare` 的标准对照图是用**打分模板的目标几何本身**渲染的
（`yoga_grid/reference.py`），这既保证图里的角度就等于模板目标值——「你和标准图的
差距」和「正位分扣掉的分」是同一件事——也避开了版权。

把别人的图嵌进生成的对照图是**再分发第三方作品**，和自己拿来看是两回事。
而且不限于版权：**任何**外部图片（哪怕是你自己拍的真人照）都会破坏上面那个等价
关系，因为它的角度未必等于模板目标值，对照反而误导。想加真人对照，正确做法是加
成额外一栏、线稿那一栏保留，别替换掉。

图上的教学口令文字同理，不要抄进 `reference.py` 的 `CUES`。要用就自己重写成
你自己的课堂说法。

## 可以用来做什么

- **决定该加哪些模板。** 这是它最大的价值。图库里有名字的体式就是一份现成的清单：
  当前 `yoga_grid` 20 个模板里 16 个在库中有对应图，另有二十多张是库里有、模板还
  没有的体式（倒立、手臂平衡、猫牛、眼镜蛇、摊尸式等）。
- **自己写发力要点时的参考。** 看着它想，然后用自己的话写。

## 和代码的关系

`python -m yoga_grid images` 会读这个目录，按文件名猜每张图标的是哪个体式
（映射表在 `yoga_grid/images.py` 的 `ALIASES`）。所以**命名要守住
`梵文 - English.png` 这个格式**，改名之前想一下映射还对不对。

差一个词就是另一个体式的，是这里最贵的错——把 A 的骨架当成 B 的真值去校准，
会把 B 的模板改坏，而且报告上看不出异常。已知的几对：

| 容易混 | 是 | 不是 |
|--------|-----|------|
| `Hanumanasana - Monkey or Splits` | 全劈叉 | 半神猴式（`ardha_hanumanasana`） |
| `Viparita Virabhadrasana - Reverse Warrior` | 反战士 | 反板式（`reverse_plank`） |
| `Adho Mukha Vrksasana - Handstand` | 手倒立 | 树式（`tree`） |
| `Ardha Uttanasana - Half Forward Fold` | 半前屈 | 站立前屈式（`uttanasana`） |
| `Utthita Chaturanga Dandasana` | 直臂斜板 | 四柱支撑式（`chaturanga`） |

穷举补不完，所以代码里是反着做的：**命中的别名没吃掉名字里的限定词
（`Adho Mukha`、`Parivrtta`、`Utthita`、`Upavistha` 等）就不下判断**，报「没敢认」
让人去确认。宁可少认，不可认错。
