# reference_images —— 第三方体式参考图

**这些图不是本项目的作品。** 绝大多数抓取自 [Yogaru](https://www.yogaru.ie)
的 Pose breakdowns 系列，图上带 `©YOGARU` 水印，是该站的商业教学产品。文件名
沿用其文章标题（`梵文 - English.png`）。少数几个该系列没有覆盖的体式是手工补的，
命名照同一格式。

留在仓库里只有一个用途：**给人看**。下面两件事都做过验证，结论是不能做。

## 不要用它们校准模板容差

`yoga_grid/README.md` 的「局限」一节记着一条已经付出过代价的教训：最初的标准骨架
照插画搭，三角伸展式和侧角伸展式的躯干竖直分量取到 0.57 / 0.50，而真实练习实测是
-0.01 / +0.10，结果**正确的模板先把自己排除在朝向门槛之外**，再被别的体式抢走。
容差后来是按真实练习数据重新放宽的。

这批图会把那个 bug 装回来。它们是扁平剪影插画：躯干是一块实色，手脚是抽象色块，
肢体互相融合，头部没有五官。在全部 44 张上跑过 `pose_landmarker_full`：

- **44 张里 10 张完全检测不到人体**，其中包括 `Tadasana - Mountain` —— 最简单的
  直立站姿。找不到人的话，其余 34 张量出来的坐标也没有理由相信。
- **面部关键点置信度中位数 1.00**，而这些图根本没有画脸。MediaPipe 回答的是「这个
  部位在画面内且没被遮挡」，不是「这里真的有」。这是唯一一个能独立验证真值的关键点，
  它确凿地错了。

要校准容差，用真人练习视频：跑一次 `python -m yoga_grid 练习.mp4`，关键点会存进
`scores.json`，之后 `rescore` 可以秒级重算。每支视频用 `-o out/日期` 各自一个目录，
否则 `scores.json` 会被下一次运行覆盖。

## 不要把它们放进程序的输出

`yoga_grid --compare` 的标准对照图是用**打分模板的目标几何本身**渲染的
（`yoga_grid/reference.py`），这既保证图里的角度就等于模板目标值——「你和标准图的
差距」和「正位分扣掉的分」是同一件事——也避开了版权。

把这些图嵌进生成的对照图是**再分发第三方商业作品**，和自己拿来看是两回事。
换成外部照片还会破坏上面那个等价关系：照片里的角度未必等于模板目标，对照反而误导。

图上的教学口令文字同理，不要抄进 `reference.py` 的 `CUES`。要用就自己重写成
你自己的课堂说法。

## 可以用来做什么

- **决定该加哪些模板。** 这是它最大的价值。图库里有名字的体式就是一份现成的清单：
  当前 `yoga_grid` 20 个模板里 16 个在库中有对应图，另有二十多张是库里有、模板还
  没有的体式（倒立、手臂平衡、猫牛、眼镜蛇、摊尸式等）。
- **自己写发力要点时的参考。** 看着它想，然后用自己的话写。

## 和代码的关系

目前**没有任何代码读这个目录**。命名保持一致是为了将来写「文件名 → 模板 key」的
映射时能精确匹配，不用猜。

两对差一个词就是另一个体式的，映射时要留意：

| 容易混 | 是 | 不是 |
|--------|-----|------|
| `Hanumanasana - Monkey or Splits` | 全劈叉 | 半神猴式（`ardha_hanumanasana`） |
| `Viparita Virabhadrasana - Reverse Warrior` | 反战士 | 反板式（`reverse_plank`） |
